## 2. Where AI got it wrong

These three examples focus on code-level issues. Each links to the commit containing the correction and describes what was wrong and how the fix was checked.

1. **Express request errors used the wrong responses.** The initial AI-assisted server setup ran the JSON parser before assigning a request ID and sent parser failures through the generic 500 handler. An unknown API path also received Express's default response instead of the API's JSON error shape. In the hardening pass, the request ID middleware was moved before parsing, malformed JSON now returns 400, oversized JSON returns 413, and unknown routes return JSON 404. The HTTP tests check those responses. [Initial server setup](https://github.com/JvlKe/smarttrip-planner-ph-/commit/e924c278eb4340867175c380274f076a456f7148), [correction and tests](https://github.com/JvlKe/smarttrip-planner-ph-/commit/93419d0a97c611bfa7967eba8165cb9d36ad16c3).

2. **The first responsive pass left an empty area beside a trip photo.** On the dashboard, the Recent Trips image occupied only part of its desktop card, leaving a blank section. I shared a screenshot and asked for the layout to be corrected. The later CSS set the image sizing for the card and added a tablet layout; the README records the resulting desktop and compact-phone behavior. This was a CSS/layout error, not a wrong-photo issue. [First responsive implementation](https://github.com/JvlKe/smarttrip-planner-ph-/commit/45ae097076cd8336481550d356517ff4b61957c8), [layout correction](https://github.com/JvlKe/smarttrip-planner-ph-/commit/804e0d8beb026ebf7726cebb9ab12b6a043090e4).

3. **A repeated-save test did not make a repeated save.** The first Favorites test draft was described as checking duplicate saves, but it sent only one POST request, so it could not check idempotency. During review, Codex pointed out that gap. I checked the test, confirmed that it needed two POST requests to exercise repeat-save behavior, and kept the correction with assertions that both calls use the same signed-in user's compound key. These are mocked HTTP/database-contract tests, not proof of live database behavior. [Correction and tests](https://github.com/JvlKe/smarttrip-planner-ph-/commit/c3ae41c39e585375c3c347541c729ce5072c1476).

### October 3 — Destination search and trip analytics

- **`server/src/routes/destinationSearch.js` — I wrote this.** I built a server-side search endpoint and connected it to the destination picker in [`client/src/pages/CreateTrip.jsx`](https://github.com/JvlKe/smarttrip-planner-ph-/blob/master/client/src/pages/CreateTrip.jsx).
  - The GET `/api/destinations/search` handler runs query parameters through a `zod` schema: it trims and caps text fields, rejects negative budgets, validates month names against a known list, and enforces that `budgetMin ≤ budgetMax` and `daysMin ≤ daysMax`. Only filters the user supplied are added to the Prisma `where` clause.
  - Text search uses case-insensitive `contains` across name, region, and description. Array columns (`interests`, `bestMonths`) use Prisma's `has` operator. AI helped me discover that Prisma uses `has` for array fields.
  - Budget filters use overlap logic: a destination matches when its range overlaps the user's requested range. The route runs count and findMany in parallel using `Promise.all`. AI helped me with the parallel query pattern.
  - I placed `app.use("/api/destinations/search", ...)` before `app.get("/api/destinations", ...)` in `index.js` so Express resolves the specific `/search` path first without breaking the existing featured-destinations route.
  - In `CreateTrip.jsx`, I replaced the upfront bulk-fetch with a debounced `useEffect`. After the picker opens and the user stops typing for 300 ms, the component sends a request. I also identified and fixed a race condition: a slow earlier response could overwrite a newer result. I added an `AbortController` so each new search cancels the previous in-flight request. AI helped me wire up the AbortController cleanup correctly.
  - Tests in `http-api.test.js` cover public access, empty and text searches, filters, invalid inputs, page limits, and pagination. AI assisted with the Prisma mock setup for these tests.
  - **Commit:** [Destination search implementation `5918358`](https://github.com/JvlKe/smarttrip-planner-ph-/commit/59183586e14fdbf1c0e456b118596d0f68abb5da)

- **`server/src/lib/tripAnalytics.js` and `GET /api/trips/analytics` — I wrote these.** I created the analytics helper and added the endpoint to [`server/src/routes/trips.js`](https://github.com/JvlKe/smarttrip-planner-ph-/blob/master/server/src/routes/trips.js), then connected the result to the Analytics page.
  - `computeTripAnalytics` skips `null`/`undefined` entries, converts budgets to integer cents to avoid floating-point drift, and groups trips by month using **UTC methods** (`getUTCFullYear`, `getUTCMonth`) so that a date-only database column is always grouped into the correct month regardless of server timezone.
  - During a Codex review, it identified that the endpoint excluded only ARCHIVED trips while the existing Analytics page UI also excluded CANCELLED trips — making the server totals inconsistent with what the page displayed. I made the correction, changing the filter to `status: { notIn: ["ARCHIVED", "CANCELLED"] }`.
  - The endpoint uses a narrow `select` (only `startDate` and `totalBudget`) to keep the query fast.
  - The Analytics page calls `api("/trips/analytics")` on mount, tracks loading and error state separately from the main trip hook, and renders a **Monthly Trends** section when data is available. AI helped with the JSX template for the monthly rows.
  - In [`server/test/tripAnalytics.test.js`](https://github.com/JvlKe/smarttrip-planner-ph-/blob/master/server/test/tripAnalytics.test.js), I wrote six unit tests covering: empty array, null/undefined skipped, non-null objects without valid dates counted but not grouped, UTC boundary grouping, floating-point cent precision, and Prisma Decimal coercion. In `http-api.test.js` I added an Analytics endpoint block covering 401, user-scoped query, correct status filter, response shape, and two-month grouping.
